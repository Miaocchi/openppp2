## 环境与方法

所有编译和测试均在获授权的共享 Linux x86_64 实验机的新任务目录中进行。
本地未编译或执行测试套件。构建持有共享构建锁，使用 CPU 0-15、nice 10，
最多 16 个并行任务；根分区必须保留至少 20 GB 可用空间。
保留证据后删除本任务的测试和构建目录。

实验机提供 GCC 14.2 和 Clang 19。GitNexus 不可用，影响分析使用源码及调用者检查、
构建定义、diff 和针对性测试。依赖 pin 和归档校验和见构建指南与 ADR。
全新下载的归档校验通过，准备后的源码与使用的依赖树一致，幂等准备检查通过。

以上 CTest 数量指注册的测试项目，不是内部断言数量。
切换测试覆盖百万次切换、嵌套、三方 transfer 接力、终止交接和顺序跨线程迁移。
Anchor 覆盖提前、重复、过期、竞争和完成后唤醒，包括随机化四 worker 调度。
独立 io_context 测试覆盖 1 和 4 个 worker。优化构建的切换计时仅用于诊断，
不能据此声称吞吐收益。

两个 Release 内核均构建成功。移除后端宏和 corocc include 路径后，332 条共同
编译命令完全一致；额外 16 条编译命令属于 corocc。默认 YieldContext 反汇编与
原始基线完全一致，SHA-256 为
`553834156d25d0143d72673d061939a83f382528f518095089f1ebd0731a5578`。
符号检查无重复定义，只链接 corocc L0 符号，仍保留 Boost make/jump 符号。
此结论限于本次 Linux/编译器构建，不代表各平台整个可执行文件逐字节一致。

最初的 ASan 链接暴露了部分离线夹具缺失依赖，失败日志已保留。
补充 allocator 定义，并为连接器夹具中未使用的可选日志器提供最小链接替身；
生产日志器和 allocator 均未修改。第一次 ASan 执行通过 202/205，三个 WSS
夹具报告泄漏。一个完全不启动协程的构造/关闭诊断在两种后端下均复现了
13,279 字节、42 次分配的相同泄漏。现已修正这三个夹具，在停止并等待 worker
退出后排空异步关闭与取消回调。上述最终 ASan/LSan 结果保留泄漏检测和
stack-use-after-return 检测。

这**不是 UBSan 全通过**：组合 ASan/UBSan 构建在现有
`nullof<YieldContext>()` 同步约定中报告三条空引用诊断，位置为 `ppp/stdafx.h`
和连接器夹具。Boost 基线复现了相同诊断。按要求保留该约定及生产调用点，
未添加新的 sanitizer suppression。

最初 TSan 执行通过 197/205，八个协程使用方崩溃。固定 L0 补丁通过强制内联
两个切换辅助函数，修复跨 fiber 的 entry/exit 插桩，保留内存读写检查。
修正后的完整套件在 103.96 秒内通过 205/205；原生对象检查确认两个辅助函数
不再有独立符号，内存访问插桩仍存在。TSan 使用仓库既有的 `libcrypto.so.3`
suppression。GCC TSan 检查使用进程级 `setarch -R`，未修改宿主 ASLR 设置。
实验机为原生 Linux，不是 WSL；脚本包含要求的 WSL
`setarch $(uname -m) -R` 路径，但 WSL 本身的执行仍未验证。

## A/B 结果

中断后的控制器继续运行，已完成全部 48 个样本，没有重跑已完成样本。
A 为 Boost，B 为 corocc，Release 构建输入仅 `ENABLE_COROCC` 不同。
native/XTCP、DL/UL、P1/P16/P64 每格按 A1/B1/B2/A2 交错，单样本 30 秒，
omit 2 秒。任务目录中的适配器调用共享 `measure.py` 控制器及其已审阅的隔离
runner，由控制器持有测量和构建锁。客户端使用两个空闲物理核的 cpuset，
关闭 kernel steering，保留宿主网络设置。共享虚拟机仅为近似隔离环境，
结果不代表生产或所有平台的性能。

## 平台

Linux x86_64 为原生验证目标。实验环境缺少 Windows、macOS、Android SDK 及适配的
交叉工具链，因此这些平台的编译和原生运行行为仍未验证。
已提供 Windows SEH/TIB 测试，但尚未执行。Linux aarch64 和 musl 也未验证。
iOS 回退检查是在 Linux 上设置 CMake 策略标志，不是 iOS 编译测试。
