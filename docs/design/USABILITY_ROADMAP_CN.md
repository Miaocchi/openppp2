# OpenPPP2 易用性路线图

> Status: Proposed
> Type: Design
> Last verified: 2026-10-08 (`claude/inspiring-galileo-ngpcc1`)
> **上一层索引：**[设计文档](README.md)

## 目标

让一个没读过源码的人，从拿到服务器地址到正常上网，全程不需要手写 JSON、不需要记命令行参数；出了问题能从界面上看懂原因，并知道下一步做什么。

衡量方式（每个阶段完成后在 Windows 真机上复测）：

| 指标 | 当前 | 目标 |
|------|------|------|
| 新用户首次连通需要编辑的 JSON 字段 | 手动节点约 6 个；完整配置 151 个键可选 | 0（订阅或分享链接导入） |
| 首次连通步骤 | 下载内核 → 选择 `ppp.exe` → 导入节点 → 以管理员重启 → 连接 | 安装 → 导入 → 连接 |
| 连接失败时能看到的信息 | 内核原始日志行；`user_message_key` 只在清理失败时填写 | 一句话原因 + 建议操作 + 可复制诊断包 |
| 搭建服务端 | 阅读手册，手写 `appsettings.json`（最小示例 23 个键） | 一条命令生成服务端配置和客户端订阅 |

## 现状与问题

以下问题都在当前代码里核对过：

1. **不带参数运行会启动服务端。** `--mode` 默认是 `server`（`ppp/app/ApplicationHelp.cpp`）。用户双击 `ppp.exe` 或误敲 `ppp` 就会监听端口。旧内核还会把不认识的 `ppp policy` 当成普通启动，所以桌面端只能靠版本号判断是否支持策略命令，不敢直接试探。
2. **配置面太宽。** 示例 `appsettings.json` 有 14 个顶层分区、151 个键，客户端和服务端字段混在同一个文件里；命令行另有 54 个参数。同一件事常有多个入口（例如 DNS 既有 `--dns`，也有 `dns`/`udp.dns`，还有策略 v2 的 `client.policy.dns`）。
3. **两代分流配置并存。** v1（`client.routing`、`dns`、`geo-rules`……）与 v2（`client.policy`）不能同时出现，否则内核直接拒绝加载。本分支已让 GUI 自动分离两者，但命令行用户仍会直接撞上 `ConfigTypeMismatch`。
4. **错误不可读。** stats 里的 `last_error.user_message_key` 基本为空，GUI 只能显示原始日志行或退出码。常见失败（端口被占用、需要管理员、证书校验失败、服务器拒绝、密钥不匹配）没有统一的用户文案。
5. **内核与 GUI 分发分离。** 桌面端需要用户自己找一个兼容的 `ppp.exe`；能力差异（P2P、策略、TCP 栈）只能靠解析 `--help` 和版本号推断。
6. **服务端到客户端没有闭环。** Go 管理后端能发布订阅（`GET /sub/{token}`），但单机部署的服务端没有"生成客户端配置/订阅"的命令，也没有分享链接或二维码。
7. **新功能默认值偏激进或尚未验收。** P2P 直连在 Windows/macOS 尚未经真实 NAT 验收（本分支已改为默认 relay）；策略 v2 的 HTTPS 场景在 Linux 实测报告中仍有失败项。

## 路线图

按用户旅程排列。每一项标注落点：内核（K）、桌面 GUI（G）、管理后端/Guardian（S）、文档（D）。

### 阶段一：装上就能用（P0）

| # | 改进 | 落点 | 说明 |
|---|------|------|------|
| 1.1 | 内核随 GUI 安装包一起发布，并做版本兼容检查 | G | 安装包内置经过测试的 `ppp.exe`；"自选内核"放进高级设置。启动时比对内核版本与 GUI 支持范围，不兼容时给出明确提示。 |
| 1.2 | `ppp` 不带 `--mode` 时打印帮助并退出 | K | 改为显式选择角色。为兼容现有部署，先保留一个版本的弃用警告：无 `--mode` 时仍以 server 启动，但打印警告并在 stats 中记录。 |
| 1.3 | 分享链接 / 二维码导入 | G、S、D | 定义 `ppp://` 之外的 `openppp2://import?sub=<url>` 或内联紧凑节点（base64url），桌面与移动端共用同一解析器；剪贴板检测到链接时提示导入。 |
| 1.4 | 首次启动向导 | G | 三步：导入（订阅/链接/手动）→ 选择模式（代理/虚拟网卡，说明是否需要管理员）→ 连接测试。向导结束即可连通，不出现 JSON。 |
| 1.5 | 管理员权限按需申请 | G | 只有选择虚拟网卡模式时才请求提升；代理模式全程普通用户。现有"以管理员重启"保留为兜底。 |

### 阶段二：出了问题看得懂（P0–P1）

| # | 改进 | 落点 | 说明 |
|---|------|------|------|
| 2.1 | 用户错误目录 | K、G | 内核在 stats `last_error` 中稳定填写 `user_message_key`（如 `AuthRejected`、`PortInUse`、`ElevationRequired`、`TlsVerifyFailed`、`ServerUnreachable`、`PolicyRejected`）。GUI 维护中英文案与"下一步"按钮（例如"换一个端口""以管理员重启""检查系统时间"）。 |
| 2.2 | 连接前预检 | G | 已有：端口占用、管理员权限、策略 v2 检查（本分支）。补充：服务器 DNS 解析、TCP 可达、系统时间偏差、残留代理设置。预检失败不启动内核。 |
| 2.3 | 一键诊断包 | G | 打包脱敏后的配置、启动参数、最近 500 行日志、stats 快照、内核能力、操作系统信息；复用现有 `kernel::redact` 与订阅 URL 脱敏。 |
| 2.4 | 连接状态时间线 | G | 把 phase 变化（解析 → 握手 → 建立隧道 → 应用路由）可视化；卡在哪一步一目了然。 |
| 2.5 | "为什么这个网站走了代理" | G | 基于本分支的 `policy explain` 测试器，在日志页对最近访问的域名一键解释命中的规则。 |

### 阶段三：调整不用写 JSON（P1）

| # | 改进 | 落点 | 说明 |
|---|------|------|------|
| 3.1 | 分流只保留一个入口 | G、D | 新用户默认进入策略 v2（模板：全部代理 / 国内直连 / 全部直连）；网络页的 v1 分流/DNS 收进"旧版设置"，提供一键迁移（本分支已接入 `policy migrate`）。 |
| 3.2 | 规则编辑器升级为结构化列表 | G | 在文本编辑之外提供"添加域名/IP 到直连/代理/拒绝"的表单视图，保存时生成 `routing.rules`；文本视图保留给高级用户。 |
| 3.3 | 规则集来源预设 | G、D | 内置常用 GeoIP/GeoSite 来源选项（可替换为自建镜像），首次连接后自动下载并校验 sha256。 |
| 3.4 | 配置分层与校验 | K、D | 拆分客户端、服务端示例配置；内核对未知键给出警告（当前静默忽略），并提供 `ppp config check --mode=client` 离线校验。 |
| 3.5 | 节点级覆盖 | G | 每个节点可单独选择模式、策略和 MUX；现有 `options` 字段已支持启动参数，补上 UI。 |

### 阶段四：服务端一条命令（P1–P2）

| # | 改进 | 落点 | 说明 |
|---|------|------|------|
| 4.1 | `ppp server init` | K、D | 交互或参数化生成服务端配置（端口、协议、密钥随机生成）、systemd 单元，并输出客户端订阅 JSON 和分享链接。 |
| 4.2 | 单机订阅端点 | K 或 S | 不部署 Go 后端也能用一个只读 token 发布订阅；或让 Guardian 承担这一角色。 |
| 4.3 | 服务端健康页 | S | Guardian 展示在线会话、P2P 协调状态、IPv6 租约与最近错误。 |

### 阶段五：新能力安全上线（持续）

| # | 改进 | 落点 | 说明 |
|---|------|------|------|
| 5.1 | 能力协商代替猜测 | K、G | 内核提供 `ppp --capabilities --json`（只输出能力、不启动任何角色），GUI 据此显示或隐藏 P2P、策略、TCP 栈、IPv6 等功能，替代解析 `--help` 和版本号。 |
| 5.2 | 实验功能开关 | G | xtcp、P2P 直连、stripe MUX 等统一放在"实验功能"区，带验收状态说明；默认关闭。 |
| 5.3 | 真机验收清单进 CI 产物 | D | 每个默认开启的功能在 `docs/testing` 中有平台验收记录；未验收平台默认关闭（本分支已对 P2P 这样处理）。 |

## 本分支已完成的基础

- 策略 v2 页面：模板、规则编辑、结构化设置、离线检查、规则测试器、迁移草稿、运行状态、手动更新、Fake-IP 重置；连接前自动 `policy check`，不通过则拒绝连接。
- v1/v2 配置自动分离，相对规则路径固定到 GUI 管理的 `policy` 目录。
- Windows 断开时发送 Ctrl+C 并等待回滚；端口映射不再被清空。
- P2P 开关与按 peer 的状态显示；TCP 栈选择与 IPv6 地址请求；`tcp_stack.active` 显示。
- 内核能力识别：只用版本号判断策略命令支持，避免在旧内核上误启动。

## 建议的推进顺序

1. 1.2（无参数不启动服务端）与 5.1（能力输出）：内核小改动，但能消除桌面端最大的不确定性。
2. 2.1 错误目录与 2.2 预检：直接减少"连不上但不知道为什么"的反馈。
3. 1.1 内置内核 + 1.4 首次向导 + 1.3 分享链接：新用户体验的主体。
4. 3.x 分流收敛：在策略 v2 的 HTTPS 场景完成验收后，再把它设为新用户默认。
5. 4.x 服务端闭环。

## 风险与约束

- 改变 `--mode` 默认值会影响现有服务端部署脚本，必须先经历一个带警告的过渡版本。
- 默认启用策略 v2 之前，需要先关闭 Linux 实测报告中 HTTPS CONNECT、SOCKS HTTPS 和 TUN HTTPS 的失败项，并补齐 Windows 真机验证。
- 分享链接与诊断包都含凭据材料：链接需要明确提示"持有即可使用"，诊断包必须经过脱敏并让用户预览。
