## 1. 目标与首版边界

同一客户端逻辑会话通过 TCP 直连、WS/WSS 反代和不同 CDN 入口并行连接同一 PPP 服务端进程。单条逻辑 TCP 业务可同时利用多条路径；单路径故障不销毁其他路径及整个会话。

首版不涉及多网卡、Wi-Fi/蜂窝聚合、跨服务端实例共享会话或服务端重启后的状态恢复。反代须固定到同一服务端进程。普通 HTTP CDN 只使用其支持的 WS/WSS，不假设支持原始 TCP。

首版交付 VMUX TCP 流聚合与连续性，覆盖建流、数据、半关闭、关闭和复位。UDP 保留数据报语义，使用选定健康承载，切换可丢包，不增加可靠重放或带宽聚合承诺。原始 IP、P2P、FRP 等通路需逐项明确覆盖情况，不能据 TCP 聚合宣称全流量聚合。

## 2. 当前基础及必须补齐的缺口

已针对以下代码和设计做过定向核对；实施前仍须在最新主线复核调用链。

| 位置 | 当前基础或限制 |
|---|---|
| `ppp/app/client/VEthernetExchanger.cpp` | 已有 TCP、WS、WSS 工厂；入口解析主要复用单个 `client.server` 和缓存 |
| `MuxConnectAllLinklayers` / `MuxGrowLinklayers` | 已有初始化与扩容入口；初始建连失败处理不能直接满足部分路径可用启动 |
| `ppp/app/mux/vmux_net.cpp` | 已有多承载、调度、重排、协商式可靠传输、承载退出与在途帧补发 |
| `VEthernetExchanger::Loopback` | 主连接结束后会取出并关闭 VMUX；必须拆开物理连接与会话生命周期 |
| `docs/design/session-recovery/l3-roaming.md` | 现有恢复保留 L3/UDP 等有限状态，不提供 VMUX/TCP 连续性 |
| `docs/design/session-recovery/noise-psk-carrier-compatibility.md` | 当前 Noise/PSK 提供认证绑定，方向密钥被销毁；WSS 使用 TLS exporter，CDN 被明确排除 |

因此多路径不是把 `client.server` 改成数组。核心改造是逐路径拨号、端到端安全承载、经过认证的会话加入、独立会话生命周期及有界恢复。

## 3. 三层模型与所有权

```text
逻辑会话：身份、虚拟 IP、业务流、控制状态、重排与重传状态
  ├─ 路径 direct：TCP 直连
  │    └─ 承载连接，可独立退出和重建
  ├─ 路径 cdn-a：WSS → CDN A → 源站
  │    └─ 承载连接
  └─ 路径 cdn-b：WSS → CDN B → 源站
       └─ 承载连接
```

- 会话拥有 VMUX 和业务状态，不由某条物理主连接拥有。
- 路径是稳定的入口配置及健康状态；每条路径可有多条承载连接。
- 承载连接拥有自己的传输对象、认证状态、加密计数器和连接代次。
- 服务端由会话所有者串行执行加入、退出和控制状态变更。不同 listener/context 的连接通过明确的异步接口交互，传输对象留在原所属执行上下文，不迁移活动 TLS/WS 对象。
- 异步请求和完成回调携带会话/连接代次，过期回调不得重新发布已退出连接。发送队列、邮箱和跨上下文请求均有上限和取消语义。

建议职责划分：路径配置与管理器、入口解析与绕行租约、拨号器、安全承载、会话加入协调器、可靠控制通道；VMUX 继续负责逻辑 TCP 数据调度与可靠交付。具体类名以代码现有组织方式为准。

## 4. 配置草案与限制

新增 `client.multipath`，默认关闭。以下为拟议配置，不是当前已支持语法：

```json
{
  "client": {
    "multipath": {
      "enabled": true,
      "policy": "adaptive",
      "max_connections": 8,
      "resume_grace_ms": 30000,
      "paths": [
        {
          "id": "direct",
          "transport": "tcp",
          "connect_host": "origin.example.com",
          "port": 443,
          "connections": 1
        },
        {
          "id": "cdn-a",
          "transport": "wss",
          "connect_host": "edge-a.example.com",
          "port": 443,
          "tls_server_name": "edge-a.example.com",
          "http_host": "edge-a.example.com",
          "ws_path": "/tunnel",
          "connections": 1
        }
      ]
    }
  }
}
```

- 最多 8 条路径；每路径默认 1 条连接，全会话默认最多 8 条连接，首版硬上限 32 条。配置目标连接数之和不得超过全会话上限。
- 路径 ID 唯一且非空；端口范围为 1–65535；只接受明确支持的协议和字段，拒绝非法 Host、路径及换行注入。
- `connect_host` 决定拨号地址，`tls_server_name` 决定 SNI 和证书校验名称，`http_host` 决定 WS Host。WSS 必须正常校验证书，不因使用 CDN 而关闭校验。
- 认证身份及密钥引用在会话层配置，复用现有密钥管理方式，不在各路径重复嵌入秘密。
- 多路径关闭时保持旧单入口行为；开启时 `paths` 为入口集合，不暗中追加 `client.server`。
- 首版入口配置为静态配置，更改通过受控重连生效。动态增删入口留待后续。

## 5. 端到端安全承载与会话加入

### 5.1 穿过 CDN 的安全边界

CDN 通常终止 WSS TLS，客户端到 CDN 的 TLS exporter 无法与源站直接对应。多路径模式统一使用客户端到 PPP 源站的内部认证加密层，覆盖 TCP、WS、WSS；外层 WSS 保留其正常入口保护。

新增版本化安全承载协议，采用标准 Noise 握手和 AEAD 记录层，优先采用经审查的实现。不得将现有仅输出 exporter 的 `noise-psk-v1` 视作现成业务加密，也不得改变其冻结语义后继续使用旧版本号。

线格式评审须冻结握手 prologue、协议版本、双方角色、身份/key-id、能力协商 transcript、密钥派生域、记录长度上限、nonce 和计数器规则。AEAD 保护内层控制与数据记录；验证失败关闭候选连接。每次重连生成新密钥，计数器耗尽前重建连接。

VMUX 重传保留内层帧身份，在目标承载上重新加密；不同承载不得复用密文或 nonce。首版不启用 0-RTT。

### 5.2 创建与加入

入口可并行建连和认证，但客户端通过协调器串行确定首次会话创建。只有一个创建意图；其他已认证候选等待创建结果，然后执行加入。

会话创建成功后得到会话实例标识、代次和会话加入凭据。凭据保存在内存，不写日志或持久化；服务端进程重启即失效。

新承载加入必须同时验证源站/客户端身份与会话所有权。证明绑定会话实例、代次、候选安全承载导出绑定、双方新鲜随机数、操作类型和请求 ID。单独知道客户端 ID、路径名或来源 IP 不足以加入。

加入过程采用有期限的预留、确认、提交及幂等结果查询。丢失最终确认时，客户端须能用同一请求查询结果；不把一次底层写成功等同于双方已一致提交。失败候选不得替换、清空或损害已有会话。

多路径能力、按流重排和可靠传输必须成功协商后才能进入多路径数据阶段。显式开启多路径却遇到旧端时返回清晰错误；不得在认证失败后静默降级。旧配置与非 multipath 的旧会话协议路径不受本功能影响，保持兼容。multipath wire 协议仅有 v1：codec 严格要求 domain `openppp2-mp-wire-v1` 与 version==1 完全相等，任何非 v1 字节一律拒绝，无跨版本协商或兼容解码；现有测试仅覆盖 v1 自洽 round-trip 与非法输入拒绝，不含跨版本字节级 fixture，不构成向后兼容声明。

## 6. 路径生命周期

```text
等待 → DNS 解析 → 绕行保护 → 建连 → 端到端认证 → 加入会话 → 可用
                   失败 / 退出 → 隔离 → 退避 → 重试
```

- 默认最多 4 个并发建连/握手尝试；各阶段有期限，取消必须释放 socket、定时器和未提交的绕行租约。
- 一条路径可用即可开始业务，其余路径后台加入，不等待全部连接建齐。
- 失败后从 1 秒指数退避到最多 30 秒，加入随机抖动。认证或配置错误单独报告并限制重试，不形成高频循环。
- 空闲时建议每 15 秒进行一次端到端探测。外层 WS ping/pong 不能替代源站可达性证明。活动连接根据进展和 RTT 动态设置停滞检测期限。
- 明确关闭立即隔离；黑洞通过探测和发送进展期限识别。单纯没有应用数据不算故障。
- 路径恢复后先以较小在途预算试运行，再增加调度份额。连接轮换尽量先建后退，遵守资源上限。

### DNS 与绕行

拨号前为实际候选 IPv4/IPv6 地址取得绕行保护，覆盖 TLS/WS 建连及认证阶段。DNS 更新先保护新地址再启用新连接；旧连接及候选均释放后才移除旧地址引用。

不同路径共享地址时使用引用计数，不因一条路径退出而删掉其他连接仍需要的保护。不同平台沿用其路由或 socket protect 能力；实现不能假设所有平台均通过新增主机路由完成。不得全量放行 CDN 地址段。

## 7. 调度、可靠性与资源预算

默认策略 `adaptive`：依据 RTT、待发送字节、在途量及近期有效吞吐估计交付成本，优先选择有发送信用且预计交付较快的连接。快速路径繁忙时其他路径参与，允许单流跨路径传输。

为避免慢路径拖住快路径，设置逐路径在途预算和会话重排预算；预算耗尽时暂停向该路径分配新数据。路径恢复、RTT 抖动和吞吐估计变化采用平滑及迟滞，避免频繁切换。双向各自调度，不能把本端写完成当成对端收到。

同时提供 `failover`：一条路径承载业务，其余已认证路径保持可接管状态。首版不默认平均轮询、不默认 FEC，不把异构路径乱序直接当成丢包。

复用 VMUX 按流序号、ACK、去重、重传缓冲与背压机制，并补齐 SYN/FIN/RST 等生命周期操作的恢复语义。明确断开的承载立即触发未确认数据补发；停滞或黑洞采用考虑原路径 RTT 的受限探测/重传，避免制造重复流量风暴。

保留既有会话和每流内存上限。新增路径队列与控制队列也须限界；无法取得预算时背压业务读取。控制流量有保留额度和速率限制，不能被数据堵死，也不能无限抢占数据。

聚合效果取决于路径是否共享瓶颈及 RTT 差异，不承诺带宽简单相加。验收必须同时观察吞吐、尾延迟、重排内存和冗余重传量。

## 8. 可靠控制通道与会话恢复

会话控制消息可以通过任意已加入承载发送，采用独立控制序号、确认、去重和幂等操作 ID。不能直接将现有无需 ACK 的 keepalive 当作可靠控制通道。控制状态由会话所有者串行提交，数据承载无需等待固定物理主连接。

| 状态 | 行为 |
|---|---|
| 创建中 | 认证候选入口，串行确定首次创建 |
| 活跃 | 至少一条承载可用，失败路径后台恢复 |
| 暂停恢复 | 所有承载失效，保留有界会话/VMUX 状态并停止读取新业务数据 |
| 恢复提交中 | 验证新承载和会话凭据，协调代次、确认区间及恢复结果 |
| 失效 | 宽限期结束、显式关闭或源站状态丢失，释放旧业务流及秘密 |

默认全断恢复宽限期 30 秒，服务端决定并在创建时告知实际期限。客户端不得自行延长。恢复失败的候选不刷新期限。

恢复期间协调缺口、重传及空闲计时器，防止 VMUX 在恢复期限前被普通缺口看门狗提前销毁；不无限暂停应用自身超时。若服务端仍连接着目标 TCP socket，需背压其读取，不能无限缓存。

恢复后核对代次和已确认数据，再补发未确认帧。采用当前代次的幂等恢复事务处理并发候选；旧代次回调不能复活会话。最后一条连接退出与新连接加入的竞争必须在同一会话所有者上确定顺序。

源站进程重启、会话确已过期或凭据失效时，关闭旧逻辑 TCP 流，再建立新会话。不得把旧流数据注入新会话。任何“恢复成功”都不承诺撤销应用超时或对端已经发生的关闭。

## 9. 可观测性

按路径 ID 显示解析/连接/认证/加入/可用/退避状态、活跃连接数、RTT、有效收发量、在途量、重传量、最近错误类别和重连次数。

当前 VMUX 运行时字节计数按稳定路径 ID 累计 VMUX 帧字节：TX 是提交给承载写操作的帧字节（包含控制帧及重传），RX 是收到的帧字节，`retransmit_bytes` 是 TX 的重传子集，因此这些值不是应用 goodput。RTT 汇总同一路径所有活跃承载的最低已采样 SRTT；没有样本时保持缺省。在途量为可靠模式下按路径汇总未确认帧字节，其他模式汇总本地待写字节。指标快照在 VMUX 维护周期发布，存在一个维护周期以内的延迟。

会话显示协商能力、实际调度策略、活跃路径数、恢复状态及剩余宽限期。区分外层连接成功、源站认证成功、会话加入成功和有效业务传输，不能用启动日志冒充可用性。

日志默认使用路径 ID 和非秘密错误码；不记录凭据、认证证明、完整连接 URL 或敏感 WS 参数。

## 10. 实施阶段与 PR 边界

| 阶段 | 内容 | 验收条件 |

| 1 | 配置、路径状态机、资源预算和取消模型 | 旧配置兼容，纯离线测试覆盖输入错误、部分失败和过期回调 |

| 3 | 会话所有权、异步接入接口与可靠控制通道 | 主物理连接退出不自动关闭 VMUX；提交确认丢失及跨 context 竞争正确 |

新工作从届时最新主线开展，与清理 PR #151、RACK PR #145 分开。关闭功能后回到旧协议需受控重建会话；不支持把运行中的多路径会话原地降级为旧协议。发布回退先停止新建多路径会话，再结束或排空现有会话后回退版本。

## 11. 测试与最终验收

先做确定性离线状态机测试、协议测试和隔离的本地传输测试。未经授权不启动 PPP 客户端，不修改路由、DNS、系统代理或活动连接。真实网络故障注入和 CDN/VPN 验收单独安排。

必须覆盖：

- TCP/WS/WSS 混合接入；WSS 在测试反代终止后仍有客户端到源站的内层保护。
- 多入口并发创建、重复加入、错误会话/密钥、重放、旧端及未知能力协商。
- 某入口启动失败、显式断开、黑洞、CDN 空闲关闭、DNS 地址变化和连接轮换。
- 原主连接退出时其他路径继续传输；所有路径中断后宽限期内恢复及超时失效。
- 加入/恢复最终确认丢失、重复请求、最后承载退出与新承载加入竞争、迟到回调。
- 单流和多流下载/上传、双向传输、FIN 半关闭、RST、目标端背压；逐字节一致且无重复交付。
- 显著不同 RTT、限速路径、共享瓶颈；验证慢路径不会导致无界重排和缓存。
- 恢复期间内存有界、源站重启后旧流明确失败、重复失败不无限延长会话保留。

性能结果以同环境最佳单路径为对照，报告吞吐、延迟分位数、故障恢复耗时、峰值内存和额外重传。真实吞吐不能由“所有连接均建立”推导。

协议字节布局、具体调度系数和密码库选型在对应阶段冻结并审查；本设计已确定产品范围、默认策略、生命周期和实现顺序。
