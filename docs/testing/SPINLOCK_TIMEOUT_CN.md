# spinlock_test 超时调查（2026-10-30）

## 结论与边界

本次在共享 Linux/VMware 测试机上复现了旧测试超过 120 秒仍不结束。
原因是固定 8 线程、每线程 20000 次递归竞争形成的无退避忙等压力，
而非已有证据证明的丢锁或错误内存序。RUN_SERIAL 只能隔离 CTest 内部任务，
不能隔离机器负载或虚拟 CPU 调度。0-15 亲和范围有 16 个逻辑 CPU，
因此本次空载复现不能归因于“8 个线程超过 16 核”。

gdb 全线程栈中主线程在 join，竞争者在 RecursiveSpinLock::TryEnter /
Lock_TryEnter，持有者可见递归重入或 Leave 路径。后续寄存器采样还能看到
线程进入状态门后的代码，而不是所有线程永久停在某个丢失的锁上。
这支持状态门争抢和饥饿性慢进展的解释，但不是公平性或无活锁的形式证明。
没有定位到生产锁的所有权/计数损坏；原子操作保持默认顺序一致，
递归元数据均在内部 SpinLock 保护下访问。

support/spinlock_test_stubs.cpp 的线程 ID 使用线程局部缓存的真实 TID，
与生产代码模式一致。其时钟返回 0；本测试 Enter 使用无限超时，不依赖该时钟。
此次没有修改 stub 或生产锁。

## 修改

- 竞争线程数取 hardware_concurrency，Linux 优先取 sched_getaffinity，最多 4，
  未知或单核时使用 1；不强制制造超过可用核数的压力。
- 两个压力用例每线程 2000 次，失败 TryEnter 后 yield；递归重入仍直接 Enter。
- 新增双线程、每线程 64 次的直接 Enter 回归，保留阻塞路径覆盖。
- 保留精确计数、递归状态、错误释放断言和 RUN_SERIAL / TIMEOUT 120。

## 远端证据

所有编译均在指定测试机的新实验目录执行，使用
`flock /tmp/ppp-m2-build.lock taskset -c 0-15 nice -n 10`。
本地未编译或运行测试。根分区从约 50GB 降至约 48GB 可用。

优化构建为 RelWithDebInfo；运行参数均为 `--log_level=test_suite`。
人为负载是 16 个分别绑定 CPU 的低优先级 `sha256sum /dev/zero` 工作者，
均由采样程序 finally 回收，没有中断其他人的进程。

| 组别 | 次数 | 结果 | 中位数 / P95 / 最大值（秒） |
|---|---:|---|---|
| 旧版完整 watchdog | 1 | 121.07 秒后终止，未完成 | 非完成时间 |
| 旧版空载短采样 | 30 | 全部超过 3 秒窗口 | 截尾，不估算完成时间 |
| 旧版负载短采样 | 30 | 全部超过 3 秒窗口 | 截尾，不估算完成时间 |
| 修后空载 | 50 | 全通过 | 0.01577 / 0.01585 / 0.01610 |
| 修后负载 | 50 | 全通过 | 0.06394 / 0.06529 / 0.06782 |

旧版短采样在 3 秒时抓全部线程栈，然后终止，包含 gdb 开销的总时间约
3.97–4.58 秒；这些不是完成耗时，也不能当作 60 次 CTest 超时。
为了不持续占用共享机两小时，没有收集旧版各 30 次完整的完成时间分布。

  CTest 使用 `-R '^spinlock_test$'`，其余 sanitizer 参数与脚本一致。
  1/1 通过，0.13 秒，无竞态报告；没有声称整个 TSan 套件通过。
- 最初全套 RelWithDebInfo 构建因编译较慢主动中止，改为脚本默认构建。
  该次中止不计入验证通过结果。
- 修后绑定单个 CPU 执行全部 6 个用例通过（约 0.0027 秒）。
- 回滚脚本在独立副本上恢复原源码，SHA-256 与原版完全一致；重新配置、
  编译后的回滚目标再次超过 3 秒窗口（含抓栈共 4.019 秒，终止码 -9）。

  CMake 生成失败，补齐后重跑成功，未更改原工作目录。
