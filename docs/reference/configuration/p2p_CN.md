# P2P 对端直连

两台客户端访问彼此的虚拟 IP 时，可以直接通过 UDP 传输，减少经服务器绕行的延迟和中转流量。服务器负责协调连接。直连不可用时，虚拟子网流量仍可经服务器中继。只借服务器访问互联网时，可以省略整个 `p2p` 块。

## 启用直连

1. 先确认两台客户端都连到同一台服务器，能够通过虚拟 IP 互访。服务端需开启 [`server.subnet`](server_CN.md#subnet)。桌面代理客户端还需要加入虚拟子网，详见[代理模式](../../guides/PROXY_MODE_CN.md)。
2. 服务端和两个客户端都需要支持经过认证的会话。使用 `ppp://`（TCP）或普通 WS 时，在服务端和两个客户端上配置匹配的[传输认证](security_CN.md#transport-auth)。直连还需要客户端能从物理网络发送和接收 UDP。
3. 将下面的 `p2p` 块合并到三份配置的 JSON 顶层，与 `client` 或 `server` 同级。

```json
{
  "p2p": {
    "enabled": true,
    "mode": "direct-preferred"
  }
}
```

访问另一台客户端的虚拟 IP，然后在客户端交互终端输入 `openppp2 peer status`。按 `Virtual IP` 找到对端，`State` 显示 `Direct` 表示直连已建立。`Relay` 表示当前经服务器中继。如果始终是中继，先检查三端的模式与传输认证，再检查两台客户端之间的 UDP 可达性。

## 模式与地址发现

| 字段 | 省略时 | 使用时机与效果 |
|---|---|---|
| `p2p.enabled` | `true` | 服务端和客户端均生效。设为 `false` 停止协商直连，虚拟子网使用服务器中继。 |
| `p2p.mode` | Linux、Android、iOS 为 `direct-preferred`，Windows、桌面 macOS 为 `relay` | `direct-preferred` 允许尝试直连并在失败时回退。`relay` 固定使用服务器中继。未知值按 `relay` 处理。 |
| `p2p.stun.servers` | `[]` | 填写最多三个 STUN 服务地址，格式为 `IP:端口`。客户端使用这些服务发现 NAT 分配的公网 UDP 地址，供对端尝试连接。空列表跳过 STUN 查询，仍可尝试已有候选地址。 |
| `p2p.stun.request-profile` | `standard` | 控制客户端 STUN 请求的格式。服务要求 tailnode 格式时选 `tailnode`，请求会附带软件标识和指纹。其他值使用标准请求。 |

## 心跳与回退

这些值在客户端生效。链路偶尔丢包、频繁退回中继时，可先调整漏收容忍次数。时间单位均为毫秒。

| 字段 | 默认值与范围 | 调整效果 |
|---|---|---|
| `p2p.heartbeat-interval-ms` | `1000`，500–5000 | 空闲直连路径的心跳间隔。缩短可更快发现中断，也会增加探测流量。 |
| `p2p.heartbeat-miss-max` | `2`，1–10 次 | 达到连续漏收阈值时，路径进入 `Suspect`。增大可容忍短暂丢包，但发现故障更慢。 |
| `p2p.suspect-timeout-ms` | `2000`，500–10000 | 进入 `Suspect` 后给路径的恢复时间。缩短会更早放弃失效路径。 |
| `p2p.migration-grace-ms` | `5000`，配置范围 1000–30000 | NAT 更换公网地址或端口后，验证新路径的等待时间。当前 v2 通道最多等待 5000 毫秒。 |

## 兼容字段

现有配置可保留下列整数。当前 v2 直连路径不使用它们来调整打洞、心跳或内存占用。

| 字段 | 默认值 | 配置范围 | 原用途 |
|---|---|---|---|
| `p2p.punch-timeout` | `5` 秒 | 至少 1 秒 | 打洞超时 |
| `p2p.keep-alived` | `15` 秒 | 至少 1 秒 | 保活间隔 |
| `p2p.max-probes` | `2` 次 | 1–10 | 旧通道的探测轮数 |
| `p2p.probe-timeout-ms` | `2000` 毫秒 | 500–10000 | 旧通道每轮探测的等待时间 |
| `p2p.buffer-pool-count` | `64` | 8–256 | 旧通道缓冲池的缓冲区数量 |
